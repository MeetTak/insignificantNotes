SOLID principle - [https://www.baeldung.com/solid-principles?utm_source=chatgpt.com](https://www.baeldung.com/solid-principles?utm_source=chatgpt.com)

- Single Responsibility

**a class should only have one responsibility. Furthermore, it should only have one reason to change.**

- Open for extension, closed for modification

**classes should be open for extension but closed for modification.** **In doing so, we** **stop ourselves from modifying existing code and causing potential new bugs**

- Liskov Substitution Principle - [https://tusharghosh09006.medium.com/liskov-substitution-principle-lsp-744eceb29e8](https://tusharghosh09006.medium.com/liskov-substitution-principle-lsp-744eceb29e8)

states that objects of a superclass should be able to be replaced with objects of a subclass without affecting the correctness of the program. in simple words **if class *A* is a subtype of class *B*, we should be able to replace *B* with *A* without disrupting the behavior of our program.**

- Interface Segregation Priciple

**arger interfaces should be split into smaller ones. By doing so, we can ensure that implementing classes only need to be concerned about the methods that are of interest to them.**

- Dependency Inversion Principle

high-level modules should not depend on low-level modules; both should depend on abstractions. Additionally, abstractions should not depend on details; details should depend on abstractions.
